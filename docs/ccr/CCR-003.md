# CCR-003 — I2 outreach API endpoints (C8, C9)

Status: **APPROVED and EXECUTED** (2026-10-25). Contract version `0.2.0` → `0.3.0`.
Filed: 2026-10-24 by the Lead. Affects **C8** (HTTP API) and **C9** (generated TS client).
Contract version: `0.2.0` → `0.3.0` (additive; one bump after both lanes land).

## What

Give the Wave 2A outreach endpoints real request bodies, response models and status codes, and
regenerate `contracts/openapi/openapi.json` and `contracts/generated_ts/src/api.d.ts`.

Pre-registered stubs this covers: `approveMessage`, `sendMessage`, `getThread`, `verifyBacklink`,
plus any additional endpoints added **inside those existing route modules**.

## Why

Wave 2A's brief includes "I2 API endpoints". The outreach slice cannot be driven or inspected
without them, and every one of these routes is currently a `501` stub with no schema, so the
committed snapshot and TS client type nothing for them. Both artefacts are frozen and Lead-only.

## Scope boundary

- `contracts/python/src/kb_contracts/**` is **not** edited apart from `CONTRACT_VERSION`.
  Response models reuse the already-frozen C2 DTOs.
- Request bodies live in `apps/api/src/kb_api/schemas/`, inside Lane B's tree, so no new type
  enters the frozen contract package.
- `apps/api/src/kb_api/routes/__init__.py` (the frozen router registry) is **not** edited.
  There is no `replies`, `opportunities` or `negotiations` route module; endpoints go inside the
  existing modules. **If a genuinely new module turns out to be necessary, that is a separate
  CCR and the lane must stop rather than edit the registry.**
- No enum, state machine, policy, tool-allowlist, provider protocol or event envelope change.

## Considered and found *not* to require a CCR

| Candidate | Why no change is needed |
|---|---|
| The five unemitted send block codes | `DUPLICATE_CONTACT`, `DUPLICATE_STEP`, `SEND_LIMIT_EXCEEDED`, `SENDER_INVALID`, `UNSUPPORTED_CLAIM` already exist in frozen C6. |
| Draft / reply / negotiation / verification agent I/O | `DraftMessage`, `DraftClaim`, `ReplyClassificationResult`, `NegotiationPlan`, `VerificationAmbiguityResult` already exist in frozen C3. |
| Message / sequence / opportunity / backlink machines | Already in frozen C1 and docs/13. |
| New job types | `scheduled_jobs.job_type` is free text; the worker's handler registry is injected. No contract surface. |
| `MockEmailProvider` | Implements the frozen C5 `EmailProvider` protocol as written. |

## Breaking?

No. Additive typing of previously untyped `501` stubs with no consumers. `0.2.0 → 0.3.0`.
