# CCR-005 — Digital PR / Earned Media channel contracts

Status: **PROPOSED. NOT APPROVED. NOT EXECUTED.** Filed 2026-10-25 by the Lead.
Depends on ADR-0021 being accepted. Contracts remain **frozen at `0.4.0`** until this is
approved; if approved it lands as **one bundled revision `0.4.0 → 0.5.0`**.

Enumerated now so the scope is visible before anyone writes code, per ADR-0016.

## Why one bundled CCR

The channel needs touches in six contract areas. Landing them piecemeal would mean several
version bumps and a window where the contracts describe a half-built channel. One revision,
approved as a unit, keeps the frozen surface coherent.

## Proposed changes

### C1 — enums and state machines

- `AgentName`: add `MEDIA_RESEARCH`, `PITCH`.
- New `ResearchAssetStatus`: `DRAFT`, `SOURCING`, `REVIEW`, `PUBLISHED`, `NEEDS_REFRESH`,
  `RETIRED`; plus its transition table in `state_machines`.
- New `PitchStatus` and its transition table, isomorphic to `MessageStatus` so the
  never-blind-resubmit discipline transfers.
- New `AcquisitionChannel`: `GUEST_POST`, `DIGITAL_PR`.
- **No change** to `BacklinkStatus` or `QualificationOutcome`.

### C2 — domain DTOs

- New: `MediaOpportunity`, `MediaOpportunityScore`, `ExpertProfile`, `ResearchAsset`,
  `ResearchAssetStatistic`, `Pitch`, `PitchSubmission`.
- `PolicyBody` additions (defaults chosen to fail closed):
  - `allow_pitch_when_publisher_unknown: bool = False` — with the publisher unknown, pitching
    requires an explicit approval rather than being silently permitted.
  - `min_asset_source_domains: int = 8`, `max_statistic_age_years: int = 3`,
    `min_recent_statistic_ratio: float = 0.6` — the asset sourcing gates.
  - `daily_pitch_limit: int = 10`, `per_publication_pitch_limit: int = 1`.
  - `require_approval_for_pitch: bool = True`.
- `Backlink`: add `acquisition_channel: AcquisitionChannel = GUEST_POST` and
  `media_opportunity_id: UUID | None = None`. Defaulted so every existing row and caller is
  unaffected.

### C4 — tool allowlists

- `MEDIA_RESEARCH`: `search`, `fetch_page`, `read_memory`, `record_evidence`,
  `record_asset_outline`.
- `PITCH`: `read_thread`-equivalent (`read_opportunity`), `read_evidence`, `read_policy`,
  `read_memory`, `record_pitch_draft`.
- **No new entry in `FORBIDDEN_CAPABILITIES`** and no existing agent gains a tool. Neither new
  agent gets a submission tool: submission is deterministic only.

### C5 — provider protocols

- `MediaOpportunityProvider`: `fetch_opportunities(since, topics)`.
- `PitchSubmissionProvider`: `submit(pitch)` (idempotent by key), `fetch_outcomes(since)`.
- Supporting DTOs: `MediaOpportunityResult`, `OutboundPitch`, `PitchReceipt`,
  `PitchOutcomeEvent`. Both use the existing error taxonomy; no new exception types.

### C6 — policy block codes

Add: `OPPORTUNITY_EXPIRED`, `DUPLICATE_PITCH`, `PITCH_LIMIT_EXCEEDED`,
`PUBLISHER_UNKNOWN`, `ASSET_NOT_PUBLISHED`, `EXPERT_PROFILE_INVALID`.

`PUBLISHER_UNKNOWN` is the Digital PR analogue of `METRIC_MISSING`: it blocks rather than
defaults, so FR-42 ("pending, never invented") is enforced by the gate and not by convention.

### C8 / C9 — HTTP API and generated client

New endpoints inside **existing** route modules wherever one fits, so the frozen router registry
is not edited. A genuinely new module (`media`, `pitches`, `assets`) would be a **separate CCR** —
flagged now because it is likely, and must not be slipped in.

Read: list/get opportunities and scores, expert profiles, research assets and their statistics,
pitches and submissions. Write: create/approve an expert profile, build/publish an asset,
draft/approve a pitch, and **enqueue** a submission (202 + job reference — never an inline
submit). Plus channel filters on the existing backlink endpoints.

## Impact analysis

| Question | Answer |
|---|---|
| Migration | **Yes — `0002`**, additive: 7 new tables, 2 nullable columns on `backlinks`, new guard/append-only triggers matching the existing conventions. No existing column altered or dropped |
| OpenAPI / TS regen | Yes, once, at execution |
| Breaking? | No. Every DTO addition is defaulted; no field removed or retyped; no `operation_id` changed |
| Seed policy `content_hash` | **Changes again** (the hash digests `PolicyBody`). Must be disclosed and the stale literal corrected, as CCR-004 did |
| Frozen router registry | Not edited — unless a new module proves necessary, which is a separate CCR |

## Considered and found NOT to need a change

| Candidate | Why not |
|---|---|
| A new `QualificationOutcome` for "pending" | `DEFERRED` already means "required input missing"; a new `PUBLISHER_UNKNOWN` block code carries the reason without touching the enum |
| A new `BacklinkStatus` for a citation | A citation is a backlink. `EXPECTED → FOUND → VERIFIED` already fits, and `{VERIFIED}` stays the only active state |
| New job-queue mechanism | `scheduled_jobs.job_type` is free text and the registry is injected; six new types need no contract change |
| A new verification provider | The existing `CrawlerProvider` verifies a citation exactly as it verifies a guest-post link |
| Changes to `EmailProvider` | Pitch submission is a platform action, not email |
