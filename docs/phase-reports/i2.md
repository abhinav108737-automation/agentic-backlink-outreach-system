### Typed job registry and composition root

`kb_runtime.jobs.build_registry` binds each **frozen job-type constant** to a closure that
already holds its dependencies. No callable name, module path, attribute or import ever comes
from a payload; there is no `getattr`, `importlib`, `eval` or service locator on the dispatch
path. A declared job type with no handler, or a handler for an undeclared type, is a **startup
error** rather than a job that silently dead-letters. Verified: the registry covers all seven
declared types exactly.

`kb_runtime.composition.build_outreach_stack` is the one place that sees deterministic services,
providers, the agent runtime and the registry together. `kb_runtime.worker` is the bounded
separate process (`python -m kb_runtime.worker --iterations N`); there is no always-on loop, and
FastAPI still only enqueues.

The three previously unwired capabilities are live: `read_thread`, `record_classification`,
`record_negotiation_plan`.

### Deterministic classification remains the safety authority

The Reply and Negotiation agents interpret; the deterministic services decide. This is
structural, not advisory:

- The final `reply_class` is **copied from the deterministic result** and never from the model. A
  model that echoes a different class fails the run (`deterministic_class_conflict`) *before*
  anything is recorded — verified for `opt_out` and `bounce` against all seven other classes.
- `suggested_action` is a closed vocabulary with no suppress, approve, send or transition
  member, further narrowed per class (`opt_out` and `bounce` allow only `no_action`).
- `makes_binding_commitment` is a **one-way ratchet**: the agent may raise it, and a `false`
  from the model cannot lower what the deterministic detector finds.
- `record_classification` deliberately does **not** write `reply_classifications` — it audits the
  agent's view as advisory, so an agent cannot restate the class as though it had decided it.
- `AGREED` remains reachable only through an APPROVED approval row.

**Independently verified by the Lead, not taken on report:** the agent-side commitment mirror's
regex equals `kb_core`'s, and the drift test is non-vacuous — perturbing the core regex failed
it, restoring it passed.

### A correction I made to Agent B's work

Agent B had campaign pause and kill switch **cancel the sequence to CANCELLED**, which is
terminal. That is wrong: `docs/13` defines campaign status as `ACTIVE ⇄ PAUSED` and a kill switch
exists to be released, so pausing a campaign would have permanently destroyed every in-flight
sequence with no way to get them back.

Now: **suppression cancels** (the recipient is off limits, nothing to resume), while **pause and
kill switch hold** — the sequence keeps its waiting state, the timer is re-armed, and the hold is
audited. Re-arming rather than raising also stops a long pause from burning the job's bounded
retries and dead-lettering the sequence. A new test proves a held sequence **resumes and proceeds
after the campaign is reactivated**.

### Follow-up scheduling (Agent B)

Delays come from policy and are measured from the previous *successful* send, not scheduling
time. The sending window is timezone-aware with DST handling tested in `Europe/London` and
`America/New_York`, including a spring-forward gap and a fall-back repeat. An out-of-window
dispatch is deferred to the next in-window instant — never dropped, never early. `begin_send`
re-evaluates policy, approval, idempotency and sender eligibility immediately before dispatch,
and the six outcomes are unchanged (no seventh was invented).
