# Phase Report — Integration Checkpoint I1

Date 2026-10-23 · branch `foundation/g0-gate` · base `0f71f0c` · contracts **0.2.0** (unchanged)
Lead-only integration. No subagents were used. No Wave 2 work was started.

## Verdict

**I1 PASSED.** The vertical slice is **agent-driven end to end**: Discovery → Qualification →
Research → Contact, with agents acting only through the real ToolGateway, persisting through
real repositories, audited, and readable back over the HTTP API.

## What was wired

`kb_core.agentic` is the composition root — the one place that sees both the agent runtime and
the database.

| Capability | Backed by |
|---|---|
| `read_campaign_state` | `CampaignRepository.get` + `list_targets` (topics, seed keywords) |
| `read_policy` | `PolicyRepository.active_version_for_campaign` |
| `read_memory` | returns no snippets — MemoryService is Wave 2 (see "Honest gaps") |
| `search` | `MockSearchProvider` over `fixtures/serp/` |
| `fetch_page` | `MockCrawlerProvider` over `fixtures/sites/`, http(s) only |
| `read_domain_metrics` | `MockSEOMetricsProvider` → persisted to `domain_metrics` → read back via `latest()` |
| `read_evidence` | `EvidenceRepository.list_for_prospect` |
| `record_candidates` | domains + prospects + prospect_urls, with provenance and audit |
| `record_assessment` | audited as **advisory**; it decides nothing |
| `record_evidence` | `EvidenceRepository.record_many`, deduplicated on content hash |
| `record_dossier` | `DossierRepository.create` + guarded `RANKED → RESEARCHED` |
| `record_contact_candidates` | contacts + channels + guarded `RESEARCHED → CONTACT_READY` |

Run persistence is the real `AgentRunRepository`; the gateway's recorder is `RunStoreRecorder`,
so every tool call — including refusals — lands in `tool_calls` against an `agent_runs` row.
The policy gate is the deterministic `PolicyEngine`, consulted before any write tool dispatches.

## The three metric states are preserved

Verified through the real gateway, not merely in the services:

| State | Representation | Required metric ⇒ |
|---|---|---|
| fetched with a value | finite float | evaluated against the threshold |
| fetched but unavailable | `None` (key present) | **DEFERRED**, reason `METRIC_UNAVAILABLE:<m>` |
| never fetched | key **absent** | **DEFERRED**, reason `METRIC_NEVER_FETCHED:<m>` |

`read_domain_metrics` persists each reading first (unavailable readings as SQL `NULL`) and then
reads back through `latest()`, so the DEFER decision is reproducible from the database alone and
the metric snapshot is auditable. Nothing is coerced to zero or NaN.

All four missing-metric cases DEFER and are asserted separately: the three corpus domains with a
blank required value, plus a domain with no readings at all.

## Agent containment

Agents receive exactly twelve capabilities and nothing else — no session, connection, engine,
provider handle or secret. Verified under test against the **real** wired gateway:

- All 7 `FORBIDDEN_CAPABILITIES` refused, for the acting agent, and audited.
- An out-of-scope but genuinely-wired tool (`record_dossier` for DISCOVERY) refused.
- Prospect count unchanged across every refusal: a refused tool writes nothing.
- `fetch_page` refuses `file://`, `ftp://` and `mailto:` — no unrestricted HTTP.
- No policy override: the gate is consulted before dispatch and an agent cannot reach it.
- No direct email send: the capability does not exist in the mapping.

Import-linter still enforces that `kb_agents` cannot import `kb_core.db` or the
crawler/email/browser providers.

## Integration findings (surfaced by wiring, fixed or recorded)

1. **`CampaignRepository` had no way to read campaign targets.** Discovery needs the campaign's
   topics and seed keywords, and the only alternative was handing an agent the database. Added
   `list_targets` to the seam (additive read) and implemented it. No migration.
2. **`record_candidates` first returned an extra `created` count.** `RecordAck` forbids extra
   keys, so the gateway failed the call as `invalid_tool_output` — the gateway validating
   capability output exactly as designed. The capability now matches the declared shape.
3. **`ELIGIBLE → RANKED` is guarded on a stored ranking result.** The slice now runs
   `RankingService` rather than forcing the transition. The agent's advisory relevance and
   editorial-fit scores feed the signals; the weights and score stay deterministic.
4. **Two of 21 fixture domains are not registered domains** (`blog.datapulseanalytics.io`,
   `www.energyoutlookdaily.com`) while their metrics are keyed by host. A prospect's identity is
   its registered domain, so the lookup misses and they DEFER as *never fetched*. That is
   **correct** behaviour under ADR-0015 and was left as-is: adding a subdomain-guessing fallback
   could attribute one host's metrics to another and would be exactly the kind of fabrication the
   three-state rule exists to prevent. Recorded as a corpus/identity mismatch to resolve
   deliberately, not patched around.
5. **Two of my own E2E tests initially passed for the wrong reason**, using a random
   `agent_run_id` that violated the `tool_calls` foreign key — so the gateway call failed on the
   audit write rather than on the guard under test. Both now use a real `agent_runs` row and
   assert the failure is not `audit_failed`.

## Honest gaps (not claimed as working)

- **`read_memory` returns nothing.** MemoryService and the Qdrant retrieval path are Wave 2. An
  agent must behave correctly with empty memory, and a stub that invented snippets would make
  the research path look better than it is.
- **Providers are fixture-backed mocks.** No real search, crawl or SEO provider ran. That is the
  I1 contract, not a shortfall.
- **The model is `FakeModelProvider`.** Deterministic and offline. Ollama was not exercised.
- **`kb_core` now depends on `kb_agents`**, which is an inversion: core should not depend on
  agents. None of the five existing packages can legally host the wiring (`kb_api` may not
  import `kb_agents` either), and standing up a dedicated composition-root package is a Wave-2
  decision rather than I1 integration. Existing import-linter contract 2 protects the boundary
  automatically: were `kb_agents` ever to import `kb_core.agentic`, it would reach `kb_core.db`
  transitively and the build would break.
- **CI remains externally unverified** — no Git remote (Foundation decision 4). Every result
  here is green on this machine only.
